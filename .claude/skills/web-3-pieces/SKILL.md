# หน้าเว็บ 3 ชิ้น — เดโมสดทีละ stage

พี่ป้องกำลังยืนอยู่หน้าห้อง มีเวลาไม่กี่นาที และน้อง ๆ กำลังดูจออยู่ งานของ skill นี้คือ
ทำให้ "หน้าเว็บ 1 หน้า" ค่อย ๆ โผล่ขึ้นมาทีละชิ้นต่อหน้าน้อง — **HTML → CSS → JavaScript** —
โดยที่แต่ละ stage ใช้เวลาสร้างสั้นที่สุด และเห็นความต่างชัดที่สุด

อุปมาที่ใช้ในสไลด์ (ยึดคำนี้ ห้ามเปลี่ยนศัพท์):

| ชิ้น | อุปมา | น้องต้องเห็นอะไร |
|---|---|---|
| HTML 🏗 | โครงบ้าน | หน้าดำ-ขาว น่าเกลียด แต่ "อ่านรู้เรื่อง" |
| CSS 🎨 | ทาสี แต่งบ้าน | หน้าเดิมเป๊ะ แต่สวยขึ้นทันที |
| JavaScript ⚡ | รีโมท/สวิตช์ | กดปุ่มแล้วมีอะไรขยับ |

---

## กติกาเหล็ก 3 ข้อ

**1. หนึ่งไฟล์ หนึ่งหน้า จบ**
ทุก stage แก้ไฟล์ `index.html` ไฟล์เดิม ไฟล์เดียว ไม่มีไฟล์ .css/.js แยก ไม่มีหน้าที่สอง ไม่มีลิงก์ไปหน้าอื่น
เพราะน้องสแกน QR เข้ามาที่ URL เดียว แล้วแค่กด refresh ตามทุก stage — ถ้ามีหลายหน้าเมื่อไหร่ น้องหลงทันที

**2. stage 2 กับ 3 ห้ามแตะเนื้อหาใน `<body>`**
เพราะนี่คือหัวใจของบทเรียนทั้งหมด — พี่ป้องต้องพูดได้เต็มปากว่า *"พี่ไม่ได้แก้ตัวหนังสือเลยสักคำนะ แค่ทาสีเฉย ๆ"*
วิธีทำให้เป็นจริง: **ตอน stage 1 ใส่ `class` และ `id` ที่จะใช้ในอนาคตลงไปให้ครบตั้งแต่แรก** (น้องไม่ทันสังเกตหรอก)
แล้ว stage 2 จะเติมแค่ `<style>` และ stage 3 เติมแค่ `<script>` — เป็นการ "เพิ่ม" ล้วน ๆ ไม่มีการ "แก้"

**3. โค้ดต้องสั้นและตัวใหญ่**
น้องนั่งหลังห้องต้องอ่านออก และพี่ป้องต้องรอไม่เกิน ~30 วินาทีต่อ stage
เพดาน: HTML ≤ 40 บรรทัด · CSS ≤ 45 บรรทัด · JS ≤ 25 บรรทัด
ถ้าเกิน แปลว่ากำลังโชว์ความเก่งของตัวเอง ไม่ได้สอนน้อง — ตัดทิ้ง

## เริ่มงาน (ทำครั้งเดียว ตอนถูกเรียก)

### 1) หาหัวข้อ + stage เริ่มต้น

ถ้าผู้ใช้พิมพ์หัวข้อมาแล้ว (เช่น `/web-3-pieces ร้านชานมไข่มุก`) ใช้เลย ไม่ต้องถาม
ถ้าไม่มี ให้ถามสั้น ๆ ครั้งเดียวจบ พร้อมเสนอตัวเลือกไว้ให้กดเร็ว ๆ:

> จะทำหน้าเว็บเรื่องอะไรดีครับ? (ให้น้องในห้องช่วยตะโกนมาก็ได้)
> เช่น ร้านชานมไข่มุก · ทีมบาส · วงดนตรีที่ชอบ · แมวของน้อง
> แล้วเริ่มที่ stage ไหน — 1 (HTML) / 2 (CSS) / 3 (JS)? [ค่าเริ่มต้น: 1]

**ให้น้องเป็นคนเลือกหัวข้อได้เมื่อไหร่ ให้รีบคว้าไว้** — เดโมที่น้องเป็นคนสั่งเอง น้องจะจ้องจอมากกว่าเดโมสำเร็จรูปหลายเท่า
ถ้าหัวข้อที่น้องให้มามันกว้างหรือเพี้ยน ไม่ต้องขออนุญาตแก้ ตีความให้เป็นหน้าเว็บร้าน/แฟนคลับ/โปรไฟล์ แล้วลุยเลย

### 2) วางไฟล์ + ทำ QR (ครั้งเดียว)

ที่อยู่ไฟล์ — เรียงตามลำดับความชอบ:
- ถ้ามีโฟลเดอร์ `public/` (Next.js repo นี้) → เขียนที่ **`public/demo/index.html`**
  เพราะ dev server เสิร์ฟให้อัตโนมัติ น้องเปิดได้ที่ `<โดเมน tunnel>/demo/` — URL เดียวกับที่น้องสแกนเข้ามาอยู่แล้ว
- ไม่มี → `./braincamp-demo/index.html` แล้วเปิดแบบ `file://` (น้องดูบนมือถือไม่ได้ แต่จอพี่ยังเดโมได้ปกติ)

ทำ QR ไว้ **ข้าง ๆ ไฟล์ index.html** (URL ไม่เปลี่ยนตลอดเดโม ทำครั้งเดียวพอ):

```bash
node .claude/skills/web-3-pieces/scripts/make-qr.mjs "https://braincamp.ponggun.com/demo" public/demo/qr.png
```

**QR ต้องอยู่ท้ายหน้าเว็บตั้งแต่ stage 1** ไม่ใช่กางแยกบนสไลด์ — เพราะน้องที่เพิ่งเงยหน้าขึ้นมากลางคัน
จะสแกนจากจอโปรเจกเตอร์ได้ทันทีโดยพี่ป้องไม่ต้องหยุดเดโมไปสลับหน้าจอ

อ้างถึงด้วย **`src="/demo/qr.png"` (path เต็ม ห้ามใช้ `src="qr.png"` เฉย ๆ)**
เพราะหน้านี้เปิดที่ URL `/demo` ซึ่งไม่มี `/` ปิดท้าย เบราว์เซอร์จะตีความ path แบบสัมพัทธ์เป็น `/qr.png` → รูปแตก
(ถ้าเดโมนอก repo แบบ `file://` ให้กลับไปใช้ `src="qr.png"` แทน เพราะไม่มี web root)

ห้ามใช้ QR API จากเน็ตทุกกรณี — เดโมต้องรอดแม้เน็ตห้องประชุมล่ม
แล้วย้ำกับพี่ป้องว่า **"น้องกด refresh บนมือถือทุกครั้งที่พี่เปลี่ยน stage นะ"**

หมายเหตุ: repo นี้ตั้ง rewrite ไว้แล้ว → ใช้ `/demo` ได้เลย ไม่ต้องพิมพ์ `/demo/index.html`
และของใน `public/` เสิร์ฟที่ root — **ห้ามมี `/public` ใน URL** (พลาดข้อนี้ = 404)

## Stage 1 — HTML 🏗 โครงบ้าน

เขียน `index.html` ที่มีแต่โครงล้วน ๆ

ต้องมี:
- `<h1>` ชื่อเรื่องใหญ่ ๆ, ย่อหน้าแนะนำสั้น 1 บรรทัด
- รายการ `<ul>` 3 ข้อ (เมนู / สมาชิกวง / จุดเด่น — แล้วแต่หัวข้อ)
- `<button id="...">` 1 ปุ่ม + `<span id="...">` ที่จะเป็นตัวเลขขยับใน stage 3
- `class`/`id` ครบทุกจุดที่ stage 2–3 จะใช้ (ดูกติกาข้อ 2)
- ภาษาไทย เนื้อหาพอดี 1 หน้าจอ
- **บล็อก QR ท้ายหน้า** (คัดลอกไปวางใน `<footer>` ได้เลย):

```html
    <div class="qr-box">
      <p class="qr-label">สแกนเปิดหน้านี้บนมือถือ 📱</p>
      <img class="qr" src="/demo/qr.png" alt="QR สำหรับเปิดหน้านี้บนมือถือ" width="180" height="180">
    </div>
```

  `width`/`height` ต้องใส่ตั้งแต่ stage 1 เพราะไฟล์ QR จริงกว้าง 800px — ถ้าไม่กำหนด หน้า stage 1 จะโดน QR ยักษ์กลืนทั้งจอ

ห้ามมีเด็ดขาด: `<style>`, `style="..."`, `<script>`, CDN, framework, รูปจากเน็ต
เพราะถ้าหน้านี้ "ดูดี" ตั้งแต่แรก บทเรียนทั้งหมดพังทันที — **มันต้องน่าเกลียด นั่นคือฟีเจอร์**

เสร็จแล้วเปิดจอ: `open <path>` (หรือ URL ของ dev server)
บอกพี่ป้องให้ **ซูม browser ไป 150–175% (Cmd +)** ก่อนหันจอให้น้อง

## Stage 2 — CSS 🎨 ทาสีแต่งบ้าน

เติม `<style>` ใน `<head>` **อย่างเดียว** — ข้างใน `<body>` ห้ามขยับแม้แต่ตัวอักษรเดียว

เป้าหมายคือ "ว้าว" ภายใน 3 วินาทีแรกที่น้องเห็น เลยควรมี:
- ตัวหนังสือฐาน ~20px ขึ้นไป, `<h1>` ~44px (ต้องอ่านออกจากหลังห้อง)
- สีเด่น 1 สี + พื้นหลังอ่อน ๆ (อย่าใช้ 5 สี — เละและไม่ได้สอนอะไร)
- hero มีพื้นหลัง gradient, การ์ดขอบมน `border-radius` + เงาจาง ๆ
- ปุ่มใหญ่ กดง่าย มี `:hover`
- จัด `.qr` ให้เป็นการ์ดขาวขอบมน (`background:#fff; border-radius:12px; padding:10px`) — พื้นขาวรอบ QR ช่วยให้กล้องมือถือจับติดง่ายขึ้นมาก อย่าวาง QR ทับพื้นสีเข้มหรือ gradient

เสร็จแล้วบอกพี่ป้องว่า **"กด Cmd+R"** — จังหวะ refresh คือ magic moment ของช่วงนี้ อย่าพลาดที่จะให้น้องเห็นก่อน-หลังติดกัน

## Stage 3 — JavaScript ⚡ รีโมท/สวิตช์

เติม `<script>` ก่อน `</body>` **อย่างเดียว** — ห้ามใช้ `onclick=` ใน HTML (จะกลายเป็นแก้ body)
ใช้ `getElementById` กับ `id` ที่ฝังไว้ตั้งแต่ stage 1 + `addEventListener("click", ...)`

ผลลัพธ์ต้อง "เห็นด้วยตา" ไม่ใช่ `console.log` — เช่น กดแล้วเลขวิ่งขึ้น + ข้อความบนปุ่มเปลี่ยน + ปุ่มเด้งนิดนึง
เขียนแบบตรงไปตรงมา (`let count = 0` แล้ว `count = count + 1`) ไม่ต้องโชว์ของ ไม่ต้อง arrow function ซ้อน ไม่ต้อง state management
เพราะเป้าหมายคือน้องอ่านแล้วเดาออกเองว่ามันทำอะไร ไม่ใช่ประทับใจว่าโค้ดเท่

## รูปแบบการตอบพี่ป้อง (สำคัญมาก — เขายืนอยู่หน้าห้อง)

หลังจบแต่ละ stage ตอบสั้น ๆ แค่นี้ **ห้ามพิมพ์โค้ดทั้งก้อนลง chat** (โค้ดอยู่บนจอ editor อยู่แล้ว การ dump ซ้ำคือทำให้พี่ป้องต้องกวาดตาหาว่าอะไรใหม่):

```
✅ Stage 1/3 — HTML (โครงบ้าน) → public/demo/index.html

🎤 พูดตรงนี้ (~20 วิ)
- "นี่คือ HTML ล้วน ๆ — มีแต่โครงกับเนื้อหา ยังไม่ทาสีเลย"
- "น่าเกลียดไหม? แต่อ่านรู้เรื่องนะ นี่แหละหน้าที่ของ HTML"
👉 ชี้จอตรง: หัวข้อใหญ่กับลิสต์ 3 อัน

⏭ พร้อมแล้วพิมพ์ "ต่อ" — พี่จะทาสีให้ดู
```

หลัง stage 2 และ 3 ก็รูปแบบเดียวกัน เปลี่ยนแค่บทพูด และเพิ่มบรรทัดเตือน refresh มือถือ

ก่อนขึ้น stage ถัดไป **สำเนาไฟล์ปัจจุบันเก็บไว้ก่อน** (`snapshots/1-html.html`, `2-css.html`)
เผื่อน้องถามย้อนว่า "ตอนยังไม่มี CSS หน้าตายังไงนะ" จะได้เปิดโชว์ได้ใน 2 วินาที ไม่ต้อง undo มั่ว

## เวลาไม่พอ / เน็ตมีปัญหา / อะไรก็ตามที่พัง

ในโฟลเดอร์ `assets/fallback/` มีตัวอย่างครบ 3 stage เรื่อง "ชานมพี่ป้อง" ที่ผ่านตาแล้วว่าใช้ได้บนโปรเจกเตอร์
คัดลอกทับได้ทันที ไม่ต้อง generate ใหม่:

```bash
cp .claude/skills/web-3-pieces/assets/fallback/1-html.html public/demo/index.html   # stage 1
cp .claude/skills/web-3-pieces/assets/fallback/2-css.html  public/demo/index.html   # stage 2
cp .claude/skills/web-3-pieces/assets/fallback/3-js.html   public/demo/index.html   # stage 3
```

ไฟล์ fallback อ้าง `qr.png` แบบ relative เหมือนกัน — ถ้ายังไม่ได้ทำ QR ในขั้น setup ให้รัน `make-qr.mjs` ก่อน ไม่งั้นท้ายหน้าจะเป็นรูปแตก

เดโมต้องไม่ตายกลางคัน — ถ้ารู้สึกว่ากำลังจะช้า อย่าฝืน generate ให้สวย ใช้ fallback แล้วเล่าต่อ

## น้องถามแบบนี้ ตอบสั้น ๆ แบบนี้

- *"เขียนเองทั้งหมดเลยเหรอ"* → "ไม่ต้องจำหรอก คนทำงานจริงก็เปิด Google เปิด AI ตลอด แต่ต้องรู้ว่ากำลังขออะไร"
- *"ทำไมต้องแยก 3 อย่าง"* → "เพราะแยกแล้วแก้ง่าย อยากเปลี่ยนสีก็แตะแค่ CSS ไม่ต้องรื้อเนื้อหา"
- *"ยากไหม"* → "อันที่พี่เพิ่งทำ 30 บรรทัดเอง น้องเรียนอาทิตย์เดียวก็ทำได้"
- *"AI ทำแทนได้หมดเลยไหม"* → โยงสไลด์ 24: "AI คือตัวคูณ — พื้นฐานดี×AI ถึงจะแรง"

อย่าเผลอสอนเกินขั้น: ช่วงนี้อยู่บันไดขั้นที่ 2 (หน้าบ้าน/Front End) เท่านั้น
ห้ามหลุดไปพูด DOM, framework, build tool, backend, database — น้องจะกลัวและหลุดทันที
